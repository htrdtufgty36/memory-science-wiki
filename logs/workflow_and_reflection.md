# Graph / Loop 工作流程、真實檢查與反思

## 工作圖
來源查核 → [2篇匯入] → metadata/claim/limit gate → [3篇匯入] → Wiki 建立 → Wiki 來源覆蓋 gate → 12頁大綱 → 逐頁來源映射 gate → HTML 產生 → 靜態結構 gate → 交付

任何 gate 失敗：回到該 gate 的直接上游節點修正，最多三輪。資料不足則停止並記錄。

## 哪個節點最容易失敗？
本次靜態檢查沒有失敗節點，因此不能從實測宣稱哪個「最常」失敗。就設計風險而言，最值得警惕的是「摘要→Wiki 的主張抽取」：若把研究的特定測驗條件誤寫成普遍定律，後續簡報即使版面正確也會傳遞錯誤。

## 哪些檢查應前移？
在 ingest 當下就檢查 DOI、摘要可支持的結論與適用限制；在簡報大綱產生前確認來源覆蓋；在 HTML 渲染前檢查逐頁證據對照。這樣比簡報完成後才發現無來源主張更節省修正成本。

## 限制
本專案研究整理以公開摘要為主，沒有宣稱對所有付費全文逐段查核。程式的靜態 PASS 不能代替瀏覽器實際觀看或網站公開可訪問性。
